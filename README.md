# AMML Ranking Competition 2026

Ранжирование русскоязычных фрагментов по запросу. Итоговый скор объединяет исходную **Giga-Embeddings-instruct-3B-0826** и эту же модель после дообучения LoRA. На карточке отправки Kaggle зафиксированы **0,946344 на public** и **0,953614 на private** по NDCG@10.

## Как запустить

1. Клонируйте репозиторий командой `git clone https://github.com/PEALD/amml-ranking-2026-giga.git`.
2. Импортируйте `solution.ipynb` в Kaggle Notebooks. Через **Add Input** подключите исходные данные AMML Ranking Competition 2026. Поддерживаются каталог с `train.csv` и `test.csv` или ZIP с этими файлами. Если подключено несколько копий, укажите нужный каталог или архив в переменной `DATA_PATH` первой ячейки.
3. Выберите **GPU T4 ×2**, включите **Internet** для загрузки зависимостей и фиксированной ревизии модели, затем **Save Version → Save & Run All**. Среда исходного прогона — Linux, Python 3.13, PyTorch 2.11.0+cu130. Обучение и расчёт прогнозов LoRA в исходной версии заняли около 2 ч 17 мин, отдельный расчёт для смеси — около 15 мин.
4. После успешного выполнения заберите **`/kaggle/working/submission.csv`**. В нём 13 507 строк в порядке тестовой таблицы и две колонки, `id` и `prediction`. Все промежуточные файлы создаются в каталоге текущего запуска.

Соседний `requirements.txt` применяется при запуске из клона. Для импорта отдельного ноутбука тот же перечень закреплённых версий включён в ячейку окружения. Для запуска в собственном Jupyter на Linux выберите ядро Python 3.13, установите зависимости командой `python -m pip install -r requirements.txt`, задайте `AMML_DATA` и доступный для записи каталог `AMML_OUTPUT`. Нужны две совместимые NVIDIA GPU. По умолчанию вывод сохраняется в `/kaggle/working`.

## Итоговое решение

**Подготовка.** Идентификаторы читаются как строки. Из текстов удаляются HTML-теги, мягкие переносы, невидимые символы и ударения. HTML-сущности декодируются, пробелы нормализуются. У заголовков обрезается окончание «— Википедия». Пустой заголовок заполняется, если для данного `article_id` в предоставленных таблицах наблюдается ровно один непустой очищенный заголовок. Правило использует только текстовые поля. Оно заполнило заголовки в 1 342 строках. Текст кандидата имеет вид «заголовок. фрагмент».

**Разбиение.** В обучающей таблице 31 530 пар и 3 042 запроса. Отсортированные уникальные `query_id` делятся через `KFold(n_splits=5, shuffle=True, random_state=993)`. Для финальной LoRA фолд 0 отложен целиком. Обучение использует **25 214 пар и 2 433 запроса**, валидация — **6 316 пар и 609 запросов**. В тесте 1 305 запросов. Списки кандидатов для оценки сохраняются полностью.

**Обучение.** Для каждого релевантного фрагмента подбираются два нерелевантных фрагмента этого запроса с наибольшим TF-IDF-сходством с запросом. Словарь униграмм и биграмм строится только на документах обучающей части. При равенстве оценок порядок задаёт строковый `id`. Получается 6 518 обучающих примеров. Каждый пример InfoNCE содержит запрос, один положительный документ и два отрицательных. Softmax вычисляется по этим трём кандидатам. Внешние размеченные датасеты при дообучении не используются.

| Параметр | Значение |
|---|---|
| Модель | `ai-sage/Giga-Embeddings-instruct-3B-0826` |
| Ревизия весов и кода модели | `b71168088212f0a13688514e4fc288a86106c4e4` |
| LoRA | ранг 16, alpha 32, dropout 0,05 |
| Слои | `q_proj`, `k_proj`, `v_proj`, `o_proj`, `gate_proj`, `up_proj`, `down_proj` |
| Представление | до 512 токенов, среднее по маске внимания в FP32, L2-нормализация |
| Обучение | одна эпоха, обычная LoRA, базовые веса FP16, параметры адаптера FP32 |
| Оптимизация | AdamW, learning rate 5e-5, weight decay 0,01, линейное расписание, прогрев 10%, clip norm 1 |
| InfoNCE | температура 0,1 |
| Параллелизм | DDP, 2 × T4, один пример на GPU, накопление градиента 8 |
| Контроль | 408 обновлений в исходном прогоне, сохранение каждые 50 обновлений и по итогам эпохи |

К запросу добавляется инструкция `Instruct: Given a query, retrieve relevant passages`, затем с новой строки `Query: <запрос>`. Документы кодируются отдельно. Один скор — косинусное сходство исходной Giga, второй — сходство после загрузки сохранённого адаптера. Для каждого `query_id` обе компоненты стандартизуются отдельно с `ddof=0`. При нулевом стандартном отклонении компонента полагается равной нулю. Итог равен `0.5 * z_base + 0.5 * z_lora`. Все кандидаты сортируются по убыванию этого значения.

## Эксперименты

В ранних экспериментах использовались пять фолдов по запросам. OOF — средний NDCG@10 на отложенных запросах всех пяти фолдов. Значения для финальной Giga в отдельной таблице рассчитаны на одном фиксированном фолде.

| Вариант | OOF NDCG@10 | Наблюдение |
|---|---:|---|
| BM25 | 0,7108 | Лексический ориентир |
| TF-IDF, слова / символы | 0,7150 / 0,7114 | Сходство по словам затем использовано для выбора трудных негативов |
| BGE reranker v2-m3 | 0,9386 | 2 эпохи, lr 6e-6 |
| BGE reranker large | 0,9359 | 2 эпохи, lr 6e-6 |
| ruRoberta-large | 0,9114 | 3 эпохи, lr 1e-5 |
| XLM-RoBERTa-large | 0,9035 | По подбору на OOF вес модели равен нулю |
| Взвешенное среднее четырёх реранкеров | 0,9464 | Относительные веса 0,9 / 0,6 / 0,3 / 0 |
| CatBoostRanker с оценками моделей, лексикой и метаданными | 0,9468 | Прирост 0,0004, public 0,9402 |
| Повторное обучение BGE с другим сидом | 0,9466 | В этом эксперименте улучшения не было |

На первом сабмите сочетание ruRoberta и CatBoost с одним недообученным фолдом дало 0,9105 public. На выборке из 150 запросов исходные Qwen3-Reranker-4B и Qwen3-Reranker-0.6B достигли соответственно 0,911 и 0,839. Дообучение Qwen3-Reranker-0.6B упиралось в память T4. Для следующего эксперимента использовалась двуязычная Giga, которая кодирует запрос и фрагмент раздельно.

| Giga на фолде 0 | NDCG@10 |
|---|---:|
| Исходная Giga | 0,942487 |
| Giga после LoRA | 0,929189 |
| Среднее двух z-оценок, вес LoRA 0,5 | **0,948435** |

После дообучения отдельная модель потеряла 0,013298 на фолде 0. При равных весах смесь превысила исходную Giga на 0,005948. Вес 0,5 выбран на этих же 609 запросах. Когда выбор веса и его оценку разделили по запросам внутри этого фолда, получили **0,946668**. Это оценка процедуры выбора веса. Итоговые публичная и приватная оценки в начале README относятся к тестовой отправке.

## Проверка воспроизведения

Исходный GPU-прогон выполнил 408 обновлений адаптера и получил 0,929189 после его повторной загрузки. В прогоне формирования смеси исходная Giga проверялась на 24 контрольных парах. Максимальное абсолютное расхождение с ранее сохранёнными оценками составило 0,000325.

Для объединённого ноутбука отдельно проверены обработка исходных конкурсных таблиц, границы фолда 0, метрика и формула ансамбля на сохранённых валидационных предсказаниях. При запуске ноутбук проверяет версии пакетов, веса адаптера, состав идентификаторов и конечность значений в итоговом CSV. Полный повтор этой объединённой версии на двух T4 и повторная оценка на private leaderboard отдельно не проводились.
