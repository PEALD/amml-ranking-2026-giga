



## Итоговое решение

**Подготовка.** Идентификаторы читаются как строки. Из текстов удаляются HTML-теги, мягкие переносы, невидимые символы и ударения. HTML-сущности декодируются, пробелы нормализуются. У заголовков обрезается окончание «— Википедия». Пустой заголовок заполняется, если для данного `article_id` в предоставленных таблицах наблюдается ровно один непустой очищенный заголовок. Правило использует только текстовые поля. Оно заполнило заголовки в 1 342 строках. Текст кандидата имеет вид «заголовок. фрагмент».

**Разбиение.** В обучающей таблице 31 530 пар и 3 042 запроса. Отсортированные уникальные `query_id` делятся через `KFold(n_splits=5, shuffle=True, random_state=993)`. Для финальной LoRA фолд 0 отложен целиком. Обучение использует **25 214 пар и 2 433 запроса**, валидация — **6 316 пар и 609 запросов**. В тесте 1 305 запросов. Списки кандидатов для оценки сохраняются полностью.

**Обучение.** Для каждого релевантного фрагмента подбираются два нерелевантных фрагмента этого запроса с наибольшим TF-IDF-сходством с запросом. Словарь униграмм и биграмм строится только на документах обучающей части. При равенстве оценок порядок задаёт строковый `id`. Получается 6 518 обучающих примеров. Каждый пример InfoNCE содержит запрос, один положительный документ и два отрицательных. Softmax вычисляется по этим трём кандидатам. Внешние размеченные датасеты при дообучении не используются.

| Параметр | Значение |
|---|---|
| Модель | `ai-sage/Giga-Embeddings-instruct-3B-0826` |
| Ревизия весов и кода модели | `b71168088212f0a13688514e4fc288a86106c4e4` |
| LoRA | ранг 16, alpha 32, dropout 0,05 |
| Слои | `q_proj`, `k_proj`, `v_proj`, `o_proj`, `gate_proj`, `up_proj`, `down_proj` |
| Представление | до 512 токенов, среднее по маске внимания в FP32, L2-нормализация |
| Обучение | одна эпоха, обычная LoRA, базовые веса FP16, параметры адаптера FP32 |
| Оптимизация | AdamW, learning rate 5e-5, weight decay 0,01, линейное расписание, прогрев 10%, clip norm 1 |
| InfoNCE | температура 0,1 |
| Параллелизм | DDP, 2 × T4, один пример на GPU, накопление градиента 8 |
| Контроль | 408 обновлений в исходном прогоне, сохранение каждые 50 обновлений и по итогам эпохи |

К запросу добавляется инструкция `Instruct: Given a query, retrieve relevant passages`, затем с новой строки `Query: <запрос>`. Документы кодируются отдельно. Один скор — косинусное сходство исходной Giga, второй — сходство после загрузки сохранённого адаптера. Для каждого `query_id` обе компоненты стандартизуются отдельно с `ddof=0`. При нулевом стандартном отклонении компонента полагается равной нулю. Итог равен `0.5 * z_base + 0.5 * z_lora`. Все кандидаты сортируются по убыванию этого значения.
